摘要

本說明書彙整《szpL2E 一鍵啟動階段化實踐計畫 v2.0》九個階段（階段 −1 至階段 6）之全面改寫實作成果。相較於 v1.1 舊版（依賴 FastAPI＋uvicorn＋httpx＋pydantic），v2.0 因沙箱環境實測無網路連線、無法安裝上述套件，全面改寫為 Python 3.12 標準庫零外部依賴架構（http.server 取代 FastAPI/uvicorn，urllib.request 取代 httpx），此決定同時更貼合專案一貫要求之「僅用語言內建、零外部依賴」工程風格。

九個階段已全數一鍵展示成功，run_all_demos.py 總控腳本單次執行即可依序跑完全部階段，總耗時約 17.6 秒；隨附 47 項自動化測試（unittest 標準庫）全數通過，涵蓋純邏輯單元測試與跨行程真實 socket 整合測試兩類。

1　架構總覽與 v1.1→v2.0 改版決策

1.1　環境前置檢查發現

本次改版工作開始前，依規範進行環境前置檢查，實測發現如下：

檢查項目結果
網路連線（pip install）無法連線，ERROR: No matching distribution found
cargo / rustc（Tauri 建置必要）未安裝
npm registry 存取403 Forbidden
Python 3.12 標準庫齊備（http.server, sqlite3, hashlib, secrets 等）
Node.js 22齊備

此發現直接觸發了兩項關鍵架構決策：

  1. 服務行程傳輸層：由 FastAPI＋uvicorn＋httpx＋pydantic 全面改寫為 Python 標準庫 http.server（伺服端）與 urllib.request（客戶端），對外行為介面（JSON 請求/回應、/health 端點、逾時重試）完全對齊，僅底層傳輸實作不同。
  2. Tauri 客戶端殼：因無 Rust/Tauri 工具鏈亦無法透過 npm 安裝，階段 −1 客戶端殼改以 Node.js 內建 http 模組實作功能等價之降級模擬版本，並於程式碼與本說明書中明確標注證據等級（詳見第 5 節）。

1.2　零依賴 HTTP 骨架（src/httpkit.py）

新建 httpkit.py 作為全部服務行程共用基礎設施，提供：

  • JsonHTTPServer：以 http.server.ThreadingHTTPServer 為底的最小 JSON API 伺服器，支援固定路徑路由與前綴路徑路由（用於 /contract/balance/{address} 一類端點）。
  • http_get_json / http_post_json：以 urllib.request 為底的 JSON 客戶端函式，內建逾時與有界重試（預設重試 2 次、退避 150ms）。
  • wait_health：健康檢查輪詢工具，供各啟動腳本等待子行程就緒。

此骨架本身以 5 項獨立單元測試驗證（tests/test_httpkit.py），涵蓋健康檢查、POST 回顯、錯誤碼傳遞、前綴路由參數解析、404 例外處理。

6.2　測試設計原則異動說明

v1.1 舊版採 FastAPI TestClient 做 in-process 測試（無真實 socket）。v2.0 因改用 http.server 標準庫實作，TestClient 機制不再適用，因此全面改為啟動真實子行程＋真實 socket 呼叫的整合測試方式。此改動雖然使測試執行時間略微增加（純邏輯測試仍為毫秒級，跨行程測試約 1～6 秒），但更貼近規劃書「真實跨行程 HTTP」之驗收精神，測試本身即是對系統可部署性的驗證。

8　已知限制與後續展望

8.1　本次沙箱環境限制（已誠實標注，非規格缺陷）

  • 無法建置真實 Tauri 客戶端殼（無 Rust/cargo 工具鏈）
  • 無法串接真實 IPFS 節點或 Storacha 雲端服務（無網路連線）
  • 無法部署至真實 EVM 測試網（無網路連線）
  • 無法進行大規模併發壓力測試（單機沙箱資源限制）

8.2　階段 7 展望範疇（依規劃書 T8-01/T8-02）

  • 真實 Tauri 五端（Windows/macOS/Linux/iOS/Android）編譯與安裝檔實測
  • 真實 Storacha 雲端持久化整合測試
  • 真實測試網（如 Sepolia）合約部署與 Gas 成本實測
  • 大規模併發壓力測試與去中心化計算層（Oracle）整合
  • CoW Protocol／Wormhole Bridge 真實網路交易時序實測
